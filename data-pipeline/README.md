# data-pipeline：測速資料處理

把政府開放資料整理成 App 內建的 `SpeedCam/Resources/cameras.json`。只用 Python 標準函式庫。

```bash
python3 build_cameras.py                 # 7320 主來源＋13940 國道座標＋126156 新北門架
python3 build_cameras.py --input raw.csv # 使用本機檔案（CSV 或 JSON，可重複指定）
python3 build_cameras.py --min-count 500 # 少於 500 筆就視為失敗
python3 -m pytest -q                     # 測試
```

## 處理內容

- **欄位對應**：同時支援全國版英文欄位（CityName、Address、Longitude、Latitude、direct、limit…）與縣市版中文欄位（設置地點、座標經度、拍攝方向、速限…）。
- **編碼**：UTF-8（含 BOM）與 Big5／cp950。
- **座標**：經緯度填反會自動對調；只保留台灣本島、澎湖、金門、馬祖範圍內的點。
- **方向**：「北向南」「南下」「往東」「西向」等文字 → 行車方位角；人工資料可明寫 `240.6°`（必須含度數符號，0 至不足 360）。雙向或無法判斷 → 不設方向（App 改用「照相點在前方」判斷）。
- **速限**：有多個數字時（例如「大型車60/小型車70」）取較小值。
- **類型**：依取締項目／地址判斷固定測速、闖紅燈、測速兼闖紅燈、區間、科技執法。
- **去重複**：約 11 m 內、同方向視為同一支；ID 由位置與方向產生，資料順序改變也不會變。
- **沒有變動就不改檔**：避免每週自動更新只因日期不同就開 PR。

## 官方座標與方向別門架

- **13940**：國道警方「國道公路固定式測速照相地點」。以正規化完整地址＋行向校正 7320 已有國道點；同名不同行向不誤合，不把其他取締類型新增成測速。ZIP 內 `manifest.csv` 不當資料。官方同名有不同座標／座標無效時印警告、不採最後一列覆蓋。
- **126156**：新北市「區間平均速率執法設備設置地點」。依同列長度的方向順序配對多值雙端座標，不能把一對端點任意反轉。本輪核實北宜 1～3 各雙向、環河路中央路至白馬寺雙向、壽山路往新莊，共 9 個方向。北宜 `beiyi-N-f/r`、方向別公告長度、groupID 與容許值保留；**56.6–68.6K 不在此來源**，維持原里程牌端點並警告。
- 門架改變後，先裁掉門架之外的里程牌點，再計算局部進入方向；避免北宜 1 接回門架後方、把方向算反。路形無法可靠銜接時明列警告，不覆寫原有路形／起終點連線。
- 快照 `manual/freeway_cameras_13940.csv`（177 列）、`manual/ntpc_sections_126156.csv`（14 列）均為 **2026-11-12 下載**，不是宣稱來源最後更新日。每次正常建置仍先下載；失聯、HTML 假資料、格式異常或筆數少於快照時明列原因並改用快照，避免靜默少資料。兩者皆失效時明列「未套用此來源」、保留原 7320／人工資料，新增來源不讓整體建置失敗；快照不是即時資料，撤點需人工核對。
- 每次建置列出**所有**未對應區間的相機，保留固定照相提醒，不猜其他縣市終點。中仁隧道以已核實的精確地址寫入 `sectionGroupID=zhongren-tunnel`；只有對應群組真的存在才視為覆蓋，不擴大全域 300 m 半徑。
- 國道座標按地址中的**同一國道編號**比對主線，距離 >150 m 列 ID、地址、座標與距離；缺線形也警告。異常不自動刪除（匝道可能合理，13940 本身也可能有錯）。11/12 原始 7320＋舊區間快照離線核對為 1,901 點／82 個方向、17 筆座標校正、12 處未覆蓋相機、8 處國道異常；**不是重新取得 7040 的完整線上建置結果**。

既有 `--input` 仍是隔離的本機主來源，不會偷偷下載新增兩來源。要套官方快照請另外指定（Windows 範例，輸出只放 `build`）：

```powershell
python -I -X utf8 data-pipeline\build_cameras.py --input build\raw.csv --freeway-input data-pipeline\manual\freeway_cameras_13940.csv --ntpc-input data-pipeline\manual\ntpc_sections_126156.csv --output build\cameras-offline.json
```

7040 無法下載時仍按既有規則明列略過自動區間／改畫直線，不能把這個降級產物當成完整資料。

## 自動產生區間測速（從文字）

開放資料把區間寫在「設置地點」欄位，例如「台9線68k+600m至56k+600m」「台3線103.2公里至108公里及台3線114.3公里至123.6公里」
「臺21線53.8K至51.1K(北向)/臺21線51.1K至53.9K(南向)」「台三線31.8k至30.5k」。`speedcam_data/section_text.py` 會：

- 解析道路（含中文數字路名、支線）、公里＋公尺／公里寫法、一筆多段（及、/、；）、後段省略路名
- 依「雙向」或單一方向（北向、東往西、北上…）決定產生一個或兩個方向；單向時用寫的方向校正起訖順序
- 用里程牌資料換算座標與進入方向；離開放資料的照相點超過 3 km 就視為解析錯誤並略過
- 跳過人工資料已定義的範圍；縣道、市道、只寫隧道或路口名稱的區間會略過並列在 log

`manual/sections_text.csv` 收錄開放資料沒有、但立法院附件清單（2026-05）有的區間，只用來產生區間。

## 人工維護的檔案

- `manual/sections.csv`：區間測速。起終點可以填座標，或直接填省道里程（例如 `台9`、`19`、`23.1`）：
  程式會下載公路局「省道里程坐標(里程牌標誌)」（資料集 7040）換算座標，長度用里程差計算，
  並用起點附近 100 m 的里程牌算出進入方向（山路彎曲時比起終點直線方向準確）。
  `bidirectional=yes` 會產生兩個方向的區間。換算結果會印在 log，確認後可以把座標填回 CSV。
  只有座標、沒有官方長度時會先估算，App 再用 Apple 地圖的道路距離修正，並在畫面標示「長度為估算」。
  目前收錄：北宜公路（台9線）19K–23.1K、26.2K–32.2K、33.3K–37.2K、56.6K–68.6K，表定速限 40，雙向。
  另外收錄台64 中和段（開放資料的範圍是錯的）和開放資料只寫名稱的隧道（自強、辛亥、中仁、仁水，座標來自 OpenStreetMap）。
- `manual/section_lengths.csv`：警方公告的區間偵測長度，依行駛方向蓋過里程差（新北市警局 1140919 修訂的一覽表）。
- `manual/ntpc_sections_126156.csv`、`manual/freeway_cameras_13940.csv`：官方來源的已查核回退快照，勿手改成臆測座標。
- `manual/cameras_extra.csv`：補充的照相點，欄位同縣市版原始資料。
  銀河附近新點為使用者街景標記，非精確設備座標；OSM way 655367014 北宜路三段局部往新店為 240.6°，速限未知保持空白、不做超速警示。和二段 348 號對面是不同設備，不能合併。
- `manual/route_hints.csv`：核實過的定向分支導航提示，與測速資料分開。產物 `SpeedCam\Resources\route_hints.json` 直接提交，如同道路線形不在建置時連網猜提示。

## 新增人工導航提示

在 repo 根目錄執行：

```powershell
python -I -X utf8 data-pipeline\build_route_hints.py
python -m pytest -q data-pipeline\tests\test_route_hints.py
```

每列填提示點、進入方位角、**後續確認點**（距離至少 20 m）、匹配半徑、`short_text`、完整 `instruction` 與 `source`。
現有半徑 12～15 m，上限 30 m；只依完整規劃路線的順序／方向確認分支，不依目前位置猜高架或地下道。
來源要列 OSM way ID、日期及 URL；OSM 沒有的車道／上下匝道描述明列「依使用者實測」。
目前 5 列涵蓋 6 個標記：水源南向出口及秀朗橋分岔相距約 37 m，共用一句，避免兩步互相覆蓋。

`replace_text` 只填已核實誤導的 Apple 原文片段，以 `|` 分隔；空欄表示不取代 Apple 原步驟。
只有同分支且動作點相距 ≤40 m 才取代，其他 Apple 轉彎及位置一律保留；不要寫空片段當萬用比對。
核心與 CSV builder 都拒絕無效資料，pytest 比對 CSV 與已提交 JSON 完全一致；載入失敗 App 會明列警告。
`project.yml` 已遞迴包含 `SpeedCam`，因此 JSON 自動打包；`route-probe.sh` 另外傳資源路徑，共用 Core 匹配／步驟插入。

新增提示時，補 `RouteHintTests.swift` 的真實分支／另一支／反向案例、replay 的 `hintChecks` 與檢查器預期。
驗收須列完整路線最近距離、Apple 前後原文、當時下一步、前後 300 m 語音候選及是否觸發；
規劃沒有走那條分支就列「未涵蓋」，不能拿沒觸發當通過。`-gallery -galleryBanners -galleryHints` 可預覽手機與最窄 CarPlay 尺寸，仍須實際截圖。

## 國道和白牌限制道路的線形

`build_road_lines.py` 從 OpenStreetMap（Overpass API）下載道路線形，產生 `SpeedCam/Resources/road_lines.json`，App 用來判斷路線有沒有走國道。
國道很少變動，所以結果直接放進 repo，不會在建置時下載；有新路段通車時再手動重跑：

```bash
python3 build_road_lines.py
```

- **國道**：OSM 的 `highway=motorway` 而且編號（`ref`）是 1、2、2甲、3、3甲、4、5、6、8、10。只取主線，不取匝道：快速道路常和國道共用交流道，算進去會誤判。
- **白牌限制道路**：`manual/white_plate_restricted.csv` 列的道路。只放 Apple 不算 highway、但不是平面道路的高架和快速道路（Apple 算 highway 的，避開高速時就不會走）。
  要確認某條路 Apple 算不算 highway，用「路線實測」的 compare 模式沿著那條路規劃（`scripts/ci/route-probe-elevated.json`）。
- **`namedRoads`**：供 Core 的 `RoadInstructionResolver` 校正接續道路名稱，以及建置的同國道座標稽核；舊資料缺欄位時不校正文字。2026-11-12 重建包含 10 個國道編號、134 筆有名稱的非國道主線（其中有橋隧名稱），同時更新原國道／白牌限制線形；7 個真實道路回歸測試全通過，仍須 CI plan 實測。

| 具名主線範圍 | 本次資料包含的道路（僅有名稱的部分，不保證每個入口） |
|---|---|
| 台北／新北高架與快速道路 | 水源快速道路、信義快速道路、建國快速道路、市民大道高架道路、新生高架道路、基隆路高架道路、中山高架道路、堤頂大道一／二段、洲美快速道路、環東大道、新北環河快速道路、環河南路快速道路、環河快速道路／環河路 |
| 省道快速道路 | 台61、62、64、65、66、68、72、74、76、78、82、84、86、88，以 OSM 原始路名保存（例如「西部濱海快速公路」「東西向快速公路 八里新店線」），不依編號臆造名稱 |
| 其他具名主線 | 東豐快速道路、臺南都會區北外環道路、高雄都會區快速道路、高雄港聯外高架道路、基隆港東岸聯外道路，以及具名橋梁／隧道 |

完整 134 筆名稱及實際線形以 `SpeedCam/Resources/road_lines.json` 的 `namedRoads` 為準。
只納入 `highway=motorway/trunk` 具名主線，不納入 link／一般平面道路；這不是道路禁行法規清單。
文字校正只看動作點之後最多 600 m，非國道須連續匹配至少 150 m，前 300 m 也須匹配至少 80 m；
確認接上國道、平行／橫跨、入口太短、未知或同時匹配多名稱都維持 Apple 原文，不全域替換「高速公路」。
